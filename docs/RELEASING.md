# Releasing

## Version and checks

1. Update `appVersionName` and increase `appVersionCode` in `gradle.properties`.
2. Update `CHANGELOG.md`, compatibility notes and versioned installation examples.
3. Run `scripts/format-java.sh --check`, `./gradlew testDebugUnitTest lint`, and the emulator checks in [VERIFICATION.md](VERIFICATION.md).
4. Review the source diff, license/notice, privacy exclusions and release notes. Do not commit `qa/`, `references/`, APKs or signing material.

## Sign

```sh
scripts/build-apk.sh
python3 scripts/verify-apk.py
```

The signing script uses `~/.local/share/stride-remote/signing/stride-remote.jks` and its adjacent `password` file. Set `STRIDE_SIGNING_DIR` to use another directory **outside the repository**. The first build generates a key if absent; a maintainer publishing updates must restore the existing release key instead of generating a new one. Keep secure backups. Never upload the key/password as release assets or commit them.

Outputs are `artifacts/stride-remote-<version>.apk` and `artifacts/SHA256SUMS`. Verify the exact signed APK installs and launches on an emulator. Hardware validation is a separate step, performed only with the pad stopped before updating and with a person supervising control tests.

CI builds without release signing credentials. The `.idsig` generated by apksigner is an optional incremental-install sidecar and is not required for ordinary sideloading.

To print the public certificate fingerprint:

```sh
"$ANDROID_HOME/build-tools/35.0.0/apksigner" verify --print-certs artifacts/stride-remote-<version>.apk
```

The public release certificate fingerprint is recorded in the GitHub release notes. A signature identifies the publisher and enables upgrades; it does not prove hardware compatibility.

## Publish

Commit the reviewed source, push `main`, and wait for CI. Tag exactly that commit and publish its APK/checksum:

```sh
git tag -a v<version> -m 'Stride Remote <version>'
git push origin v<version>
gh release create v<version> \
  artifacts/stride-remote-<version>.apk artifacts/SHA256SUMS \
  --verify-tag --title 'Stride Remote <version>' \
  --notes-file docs/releases/<version>.md
```

Write notes for the actual release: features/fixes, installation link, compatibility limits, verification scope and signing fingerprint. After publishing, download the public assets into an ignored local directory, verify `SHA256SUMS` and signature again, and check that the release tag resolves to the source commit. Keep the current release link in the README valid.
